## code 7
- [medium] src/game/game.js visBoard() line 620-625 clears vis.bench[e.seat] = -1 unconditionally, at time arr_C+0.44 of the tap that triggered the hop-in. visBench() (line 612) for a LATER tap can land earlier than that (arrival = t0+0.07+T, T is 0.42-0.95 s, so any second tap within about 0.5-1 s). The rules give the freed seat (lowest free index) to the new cat, so the new cat's cushion is wiped from the visual bench while rules still hold it. Chain finishes are exactly when players tap fast. Self-heals only on syncVis (undo, resize, new level); later the cat hops in from an empty cushion. Rules fuzz (tap/scoop/undo/addSeat on levels 5-120) shows rules state is consistent, so this is purely a vis-model ordering bug.
  FIX: In visBoard only clear the seat if this.vis.bench[e.seat] === e.id (and have visBench likewise skip if a pending board for that seat is still queued), or key the vis updates by cat id instead of seat index.
- [medium] src/kit/ads.js loadH5() has no timeout. h5Rewarded/h5Interstitial await it BEFORE their own START/INTER timers start. If the adsbygoogle script request stalls (captive portal, silent drop, no onload/onerror), the promise never settles, main.js guarded() leaves busy = true forever, and every guarded action (next, hint, buy, restore, adlife, adheart, share) is dead. The win card Next button then does nothing. Only reachable with VITE_ADS_PROVIDER=h5, which is the planned release config.
  FIX: Race loadH5() against a 4-5 s timer inside loadH5 itself (resolve(false) on timeout) and do not cache a timeout as a permanent failure; also make guarded() release after a max duration.
- [medium] Production gating leaves dead UI. In a default production build (ADS_CONFIG.provider 'off', AD_TEST false, iap backend fail-closed) rewarded() always returns false and purchase() always fails, yet the fail card shows 'Watch ad: +1 seat', the no-lives sheet shows 'Watch ad: +1 life', hint falls to a toast, the shop lists $ prices, and the Starter Bundle ($4.99) is shown once after L10 and then burned (shop.starterShown = true). Every one ends in 'No ad right now' / 'Purchase failed'.
  FIX: Expose ads.available() and iap.available() (provider configured or DEV) and hide or replace the ad buttons, the price tiles and the starter offer when false; do not set starterShown unless the offer was purchasable.
- [low] src/ui/ui.js settings(): cur.screen becomes 'settings' and actions.close only calls hideModal(), so ui.screen stays 'settings' after the card is gone (cafe or home keeps showing). main.js restore() (line 445) and the pwa.onChange handler (line 669) then call ui.settings() when ui.screen === 'settings'. Repro: cafe > Settings > Close > Shop > Restore, and Settings pops open over the shop. appinstalled/beforeinstallprompt fired later does the same.
